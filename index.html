0. 先给结论

数学推理冗长已经是一个非常拥挤的方向。仅提出“长度奖励”“提前停止”“难度自适应预算”“隐藏状态 steering”中的任意一个，通常不足以构成新论文。近半年的直接论文已经覆盖：动态长度奖励、最优停止、语义冗余检测、注意力/不确定性监控、隐空间投影、分段信用分配、在线 rollout 编辑、元控制器和多答案预算分配。

最值得继续做的方向是把不同层次的问题连起来：

  1. Prefix-only 的可靠停止：只用当前前缀，估计“再想一段是否还有价值”，并给出可校准的错误风险/计算保证；不要把完整轨迹中的正确答案泄漏给停止器。
  2. 负外部性下的预算分配：多个数学题共享总 token/FLOP/延迟预算时，模型要考虑继续当前题的机会成本、放弃和回收预算；这与单题压缩不同。
  3. 可验证的 load-bearing reasoning：用形式证明状态、程序执行状态或可验证的依赖关系识别真正必要的步骤，压缩自然语言外壳，而不是用 LLM judge 猜步骤是否重要。

最初我推荐方向 1，但严格撞车审计后需要修正：不能直接把它作为新算法投稿。方向 2 和方向 3 也分别撞上了近期的 rollout allocation、multi-attribute verification、counterfactual skip、set-level deletion 和 Lean proof compression 工作。按“提出候选 → 窄检索 → 精读近邻 → 淘汰撞车”的循环重做后，当前候选池如下。

重做后的候选优先级：

  1. Competing-Risk Hazard Control for Mathematical Reasoning：把继续推理可能导致的“成功完成、答案漂移、循环/超时”作为竞争事件来建模；窄检索没有发现直接把 competing-risk hazard 用于数学 CoT stopping 的论文。当前新颖性最强，但必须证明它不是普通 learned stopper 的换名。
  2. Any-Stage-Valid Stopping under Endogenous Logging and Model Drift：把停止动作导致的“后续 prefix 不再被观测”与模型在线更新结合起来，研究非 exchangeable 条件下的风险保证。COINS 和 Counterfactual Online CP 提供统计工具，但窄检索没有发现直接针对数学 CoT 的实现；理论风险最高。
  3. Censored Reasoning Curves：把 token budget 截断视为 right-censoring，同时估计 time-to-correct、time-to-drift 和 time-to-loop。它更偏 measurement/benchmark，方法创新弱一些，但可以成为可靠的基础论文，并揭露现有 accuracy–length 曲线的偏差。
  4. IRT-Hazard Budget Response Surface：把 Item Response Scaling Laws（2606.07616）和规划中的 multidimensional IRT（2607.11197）迁移到数学推理预算，但不只估计“题难/模型强”，而是让 latent ability × item difficulty 调节三种事件 hazard（correct/drift/loop）。窄检索未发现“IRT + reasoning budget + event hazards”的组合；但必须先排除仅仅复现 IRSL/MIRT 的风险。

原方向 2 的“多题共享预算”与原方向 3 的“可验证压缩”暂时淘汰为主创新：前者已被 R3-Bench、SARA、BMA-GAI、APIVIS 等覆盖，后者已被 DRSR、LW2S、LeanPolish、Minimal Witness RL、AttriCoT、load-bearing CoT 等覆盖。它们只能作为新候选的实验场景或基线。

2. 直接相关工作谱系

A. 早期基础：长度不是单调收益

  • When More is Less: Understanding Chain-of-Thought Length in LLMs，arXiv:2502.07266：指出更长 CoT 可能降低准确率，为 overthinking 的经验问题提供早期分析。
  • S1: Simple test-time scaling，arXiv:2501.19393：budget forcing/固定 test-time budget，是后来“长度—准确率前沿”的常用基线。
  • Chain of Draft: Thinking Faster by Writing Less，arXiv:2502.18600：通过短草稿减少显式 token，属于表达压缩，不解决何时停止的可靠性。
  • L1: Controlling How Long A Reasoning Model Thinks With Reinforcement Learning，arXiv:2503.04697：RL 学长度控制，是长度奖励类基线。
  • DAST: Difficulty-Adaptive Slow-Thinking for Large Reasoning Models，arXiv:2503.04472：把难度和慢思考强度绑定；必须注意它原始训练/优化协议，不能把不同版本方法混称。
  • ThinkPrune，arXiv:2504.01296：RL 剪枝长 CoT；属于“生成后/训练中删掉路径”的早期代表。
  • ShorterBetter，arXiv:2504.21370：寻找问题的近似最优推理长度。
  • AdaptThink，arXiv:2505.13417：学习何时需要显式思考；代表 mode routing。
  • ConCISE，arXiv:2505.04881：置信度引导的 step-by-step 压缩；代表 confidence/trigger 类方法。
  • ConciseRL，arXiv:2505.17250；HAPO，arXiv:2505.11225；Walk Before You Run，arXiv:2505.21178：不同形式的 concise reasoning RL。

两篇综述适合做引用入口：Reasoning on a Budget，arXiv:2507.02076；Towards Concise and Adaptive Thinking，arXiv:2507.09662；另有 Don't Overthink It，arXiv:2508.02120。它们的共同分类是 controllable/adaptive test-time compute、early exit、CoT compression、long–short collaboration、latent steering。

C. 已经很拥挤、建议不要单独投稿的题目

  • “给 GRPO 加一个固定长度 penalty”。已有 L1、ConciseRL、RECAP、ICR、DDCA/长度方向 reward 等大量基线，而且固定 penalty 会把 overthinking 推向 underthinking。
  • “检测 wait/alternatively/again 然后提前停止”。已有 ConCISE、Step-GRPO、ASAG、PUMA、Settle 等；仅换关键词不够。
  • “用 hidden state/attention entropy 做 early exit”。已有 DyCon、ASAG、UPAIR、Opt4Reasoning、PUMA 等。
  • “用语义相似度删除重复 step”。已有 PUMA、ChainPrune、CRISP、STOP、RECAP。
  • “用难度预测分配单题长度”。已有 DAST、DyCon、When2Think、Thinking Economically、To Think or Not to Think。
  • “用 latent space 做无 token reasoning”。已有 latent reasoning、Opt4Reasoning、HyperThink、SST/looped transformer 等；若做，必须给出新的计算/可验证理论，而非只换 latent encoder。

3. 近半年可迁移领域：哪些真正有用

3.1 序贯统计、conformal risk、e-process

代表工作：

  • Conformal Thinking: Risk Control for Reasoning on a Compute Budget，arXiv:2602.03814：对 reasoning confidence 设置 upper/lower threshold，用 distribution-free risk control 控制早停错误和“难题无法解”的提前退出。
  • Conformal Selective Acting，arXiv:2605.20270：面向 RLVR 部署流的 anytime/pathwise selective risk 控制。
  • MARS，arXiv:2606.12935：parallel self-consistency 的 margin-adversarial stopping，估计继续采样造成的 vote switch。
  • Calibrated e-CUSUM Decoding，arXiv:2607.11317：指出 token log-probability martingale 不能检测 confident repetition；用 repetition + entropy alarm，再做 e-process/CUSUM 校准。
  • Efficient Sequential Evaluation of LLMs，arXiv:2607.17409：confidence sequence、testing-by-betting、主动查询。
  • Uncertainty-Aware Sequential Decision Rules for Event-Triggered LLM Invocation，arXiv:2607.13048：把昂贵 LLM 调用写成风险触发 stopping，给出 regret/trigger 形式化。

可迁移点：将“停止”从 heuristic threshold 改成 对未来错误风险或边际收益的可校准序贯决策。数学题的 verifier 提供了天然的离线 calibration label；推理时只使用前缀。

局限：conformal 的 exchangeability、e-process 的 conditional-mean null、分布漂移和每题内部强相关都不能直接假设成立。论文必须把保证写成“在 calibration/test exchangeability 或指定条件下”的保证，并做 shift stress test；不要宣称任意自回归轨迹都有严格 coverage。

3.2 Value of computation / value of information / optimal stopping

代表工作：

  • AERA，arXiv:2608.27964：未来 residual utility，承认 checkpoint correctness 非单调。
  • Early Verdicts, Better Budgets，arXiv:2607.26253：Beta posterior + SPRT 的 sequential rollout allocation。
  • Thinking Hard, Not Smart，arXiv:2608.07968：提出共享总预算下的数学/代码 exam-style benchmark，暴露按顺序贪心和无价值感知分配。
  • Uncertainty-Aware Sequential Decision Rules，arXiv:2607.13048：事件触发式昂贵模型调用。

可迁移点：把每一段 CoT 视为一项有成本的实验，决策不是“当前答案够不够自信”，而是“下一段的 expected value of computation 是否超过 token/FLOP opportunity cost”。

局限：需要估计 continuation 的 counterfactual value；若训练标签使用完整未来轨迹，必须证明部署时没有泄漏。

3.3 因果 credit、反事实 rollout、可验证依赖

代表工作：

  • CRAFT，arXiv:2606.29476：复用 GRPO sibling rollouts，估计 teacher-preferred token 的 counterfactual signed credit。
  • Policy-Conditioned Counterfactual Credit，arXiv:2606.05263：删除、语义替换、证据替换、tool-output perturbation；用 doubly robust estimator。
  • Skill Reuse as Compression，arXiv:2605.31509：MDL skill dictionary、segmentation cost、PAC-Bayes 泛化界。
  • Adaptive state-action abstractions via rate-distortion，arXiv:2606.06123：Bellman residual 与 abstraction error/bisimulation metric 的性能证书，动态调整状态/动作抽象粒度。

可迁移点：不要把“长”当作唯一坏处；估计一个 step 被删除/替换后对最终可验证成功的影响，并用 dependency/MDL 保留能复用的结构。

局限：完整 leave-one-out 很贵；语义替换的干预有效性需要额外假设；自然语言数学 trace 的依赖图若由 LLM judge 产生，容易把 judge 偏差当作过程监督。

3.4 率失真、信息瓶颈、动态抽象

可迁移点：把 CoT 看成发送给同一个模型的“内部通信码”。压缩目标应是：在给定 token/bit rate 下最小化答案风险或 proof-state distortion，而非最小化文本长度。可把 reasoning prefix 映射成 state abstraction，定义任务相关 distortion（最终答案、verifier state、后续 logit 分布）和 rate（token/FLOP/KV bytes）。

已有直接占位：2603.08462 Reasoning as Compression: Conditional Information Bottleneck、2609.34181 Opt4Reasoning、2605.07316 ICR、2608.04771 ReCo。因此新的贡献必须加入可验证的 distortion 或动态抽象理论；单独使用 IB/QP 不足。

4.0.2 重要的撞车审计结论（2026-10-09）

先把结论说清楚：按本节后面给出的原始实施方案，不能声称“没人做过”。它与最近半年多篇论文的核心组件已经实质重叠。 这条方向目前更适合作为一个待重构的研究问题，而不是直接拿去投稿的方法名。

  • future computation gain 不是新点；
  • conformal risk calibration 不是新点；

诚实判断：如果把这些模块按原样组合，最多是一个工程整合或小幅改进，不能把它称作确定的新算法。 真要继续，必须选择一个现有工作没有解决、而且能够单独被实验或理论证伪的缺口，例如：

  1. 非交换、在线更新场景的 prefix stopping 保证：现有 CROP/Conformal Thinking 主要依赖 exchangeable calibration；如果模型、路由器或任务分布在线变化，如何给出有效的 anytime/shift-aware 风险保证？这个方向理论难度高，不能只换一个阈值。
  2. 停止动作的反事实因果界：不是只预测“继续通常有没有用”，而是给出“在当前 prefix 下，执行 STOP 相对 CONTINUE 的可验证 regret/upper bound”，并处理 probe 成本与自回归相关性。AERA 给了 residual value 方向，但没有自动继承这样的因果保证；需要先做严格文献和理论审计。
  3. 把 consensus–termination gap 变成新的 benchmark/负结果论文：系统展示现有稳定答案、confidence、CROP、BLADE、LearnStop 在不同 serving regime 下的净成本和错误类型，并提出一个可复现的评测协议。这更像 evaluation/measurement 论文，而不是“新停止器”。

新候选的实施草案（先做撞车前置实验，不直接训练大模型）

A. Competing-Risk Hazard Control。 对每条完整数学轨迹记录三个时间：第一次得到可验证正确答案 T_correct、第一次从正确候选漂移到错误答案 T_drift、进入重复/超时 T_loop。把未到事件的轨迹按 right-censoring 处理，用离散时间 cause-specific hazard 或 multi-state model 估计 P(event=e | prefix state, item difficulty, current budget)。第一阶段只做 measurement：检验 hazard 是否比一个普通二分类 learned stopper 更能区分“继续会纠错”和“继续会漂移”。第二阶段才做 decision rule：在给定成本和 drift-risk 权重下选择 STOP/CONTINUE。必须和 BLADE、LearnStop、Token Budget Saturation、Commitment Boundary、AERA 对照；若 hazard 模型只是把分类器换成 survival loss，直接淘汰。

B. Any-Stage-Valid under Endogenous Logging。 每次模型选择 STOP，就不再观察“如果 CONTINUE 会发生什么”；这会让训练/校准数据由策略自己选择，产生 endogenous logging。先在固定模型、可完整 replay 的轨迹池上构造反事实标签，再用 propensity-weighted / doubly robust online conformal 方法估计任意停止阶段的累计风险。主问题是：在模型更新或题目分布漂移时，能否控制“所有检查点中至少一次错误停止”的概率。必须和 CROP、COINS、Counterfactual Online CP、Conformal Thinking 对照；若只在 i.i.d. calibration 上有效，不能作为新论文。

C. IRT-Hazard Budget Response Surface。 把题目作为 item，把模型/推理预算作为 respondent-condition；用 IRSL（2606.07616）和 MIRT Planning（2607.11197）已有的能力—题目难度分解，扩展到三个事件 hazard：正确完成、漂移、循环。目标不是预测一题“难不难”，而是估计不同题型在额外 256 tokens 下的事件转移概率，并回答“哪类能力可以通过更多预算提升，哪类能力只会增加冗余”。主实验需要不同模型、多个预算点和题目级 response matrix；若模型能力/题目难度分解已经解释全部收益，淘汰该方向。

这三个候选的共同前置要求是：先完成现有方法统一 replay；没有 replay 和反事实标签，就不能声称新 hazard、因果或 IRT 机制带来增益。

4.0.1 为什么“想得更久”会提高能力，也会浪费计算

大语言模型回答一道数学题时，可以直接输出答案，也可以先生成一串隐藏或显式的中间文字：列式、试算、检查、改错、重新推导。这串中间文字就是这里说的 reasoning trace / CoT。模型每生成一个 token，都要再运行一次网络，所以 8,000 个推理 token 的成本大约是 800 个 token 的十倍量级；长上下文还会让注意力和 KV cache 继续变贵。

长推理有真实好处：难题需要更多尝试和自我纠错。但它不是“越长越好”。模型可能已经得到正确答案，却继续说“再检查一下”；也可能在正确答案后重新计算，把正确答案改错。这叫 overthinking。反过来，如果我们过早截断，模型还没有完成关键推导就被迫回答，这叫 underthinking。

因此，目标不是简单地让所有回答变短，而是让模型在“已经足够”和“还需要继续”之间做出正确决策。用一个简单例子表示：

题目：一个数先增加 20%，再减少 20%，最后变成 96，原数是多少？

有效步骤可能只有：设原数为 x，得到 1.2×0.8x=96，所以 x=100。模型随后又重复代入、重述题目、怀疑百分比方向，生成几百个 token。重复部分不一定增加正确率，却增加成本和答案漂移风险。

三条候选方向研究的是三个不同的决策层次：

方向 决策对象 一句话问题 直观比喻
方向 1 一道题的一条推理轨迹 现在该不该停？ 开车时判断是否已经到达
方向 2 多道题之间的共享计算 下一笔预算给哪道题？ 考试时间不够时先做哪题
方向 3 已有轨迹里的具体步骤 哪些步骤可以删？ 删除证明草稿中的废话，但不能删掉支撑结论的桥梁

方向 1 是在线停止；方向 2 是跨题资源分配；方向 3 是事后或训练时的可验证压缩。它们都减少 token，但研究问题、输入输出和实验指标完全不同。

方向 1（原始候选，已发现高度撞车）：Calibrated Causal Minimal-Sufficient Stopping

背景：现在的早停方法在做什么

现在最常见的早停方法，在推理过程中每隔一段检查一次：模型对当前答案的置信度是否足够高、多个候选答案是否一致、attention entropy 是否下降。如果超过固定阈值，就停止生成。

问题是：“当前看起来很自信”不等于“再想下去不会变好”，也不等于“现在停下不会错”。 简单题可能在很短的前缀就够了；难题可能暂时给出一个看似稳定但错误的答案。固定阈值还很难跨模型、跨题型复用。

这篇论文真正要问什么

给定题目 x 和已经生成的前缀 z_≤t，只看当前能看到的内容，决定：

  1. 现在停止并回答；
  2. 再生成一个小段推理；
  3. 回到前一个安全节点重新尝试。

目标不是平均变短，而是在一个明确的错误风险预算内，尽量少花 token。

用刚才的题目举例

模型生成“设原数为 x，1.2×0.8x=96，所以 x=100”后，停止器先让模型做一个短 answer probe，得到候选答案 100。它还会看：

  • 最近几个前缀的答案是否稳定；
  • 模型是否已经进入“重复检查/答案漂移”模式；
  • 再生成一个 block 后，历史上有多大概率把错误改对；
  • 当前前缀删掉某一步后，答案是否仍然正确。

如果“继续一段”的预期收益很低，而且在校准集上这种停止规则的错误率满足用户给定的 1% 或 5% 风险目标，就停；如果答案稳定但模型经常在这一状态下继续发现关键步骤，就继续。

方法分成四步

  1. 观察当前前缀：在自然句子/步骤边界读取 tentative answer、答案分布、回溯信号和隐藏状态特征。
  2. 估计继续的价值：用同一道题的 sibling rollouts、短 continuation probe 或受控删除，估计“再花 128 个 token 能否提高最终正确率”。这不是只预测最终对错，而是预测下一段计算的增益。
  3. 估计步骤必要性：如果去掉当前步骤后模型仍能得到同样答案，这一步可能是冗余；如果去掉后答案崩溃，就不应停在这里。
  4. 校准风险：在独立 calibration set 上选择阈值，使早停错误率或 selective risk 达到预先指定的目标。部署时不能读取 gold answer，也不能读取未来轨迹。

它和另外两条有什么区别

  • 它只处理 一题的一条正在生成的轨迹；不负责决定其他题拿多少预算。
  • 它的动作是 stop / continue / restart；不是删除已经生成的任意中间句子。
  • 它的关键卖点是 风险可校准 和 继续计算的边际价值，不是又一个 confidence threshold。

怎么做实验

用 Qwen2.5-Math-7B 或 DeepSeek-R1-Distill-Qwen-7B，在 GSM8K、MATH-500、AMC、AIME 上测试。训练/校准只使用问题级切分的一部分，测试集完全不参与阈值选择。比较 vanilla、固定 budget、PUMA/ConCISE、OS-Pruner、Conformal Thinking、AERA 等方法。

除了 accuracy 和 token，还必须报告：早停错误率、风险覆盖率、ECE、FLOPs、真实延迟、简单题/难题分层结果，以及分布外题目的风险失效情况。

什么结果说明它失败

如果在相同准确率下不能节省约 20% token，或者在难度变化/分布偏移后风险覆盖明显失效，那么“风险校准的最小充分停止”就没有站住。

成本会不会把节省的 token 吃掉

会，取决于实现方式。下面把最朴素但昂贵的版本，和真正适合部署的版本分开：

版本 训练/校准时做什么 部署时做什么 成本判断
朴素研究版 每个前缀都做多个 sibling rollout、删除当前步骤、再生成 answer probe 每隔很短一段重复 probe 训练数据生成可能是基线的 2–10 倍；线上也可能得不偿失，不建议作为最终系统
推荐论文版 只在离线 calibration set 上做少量 block-level continuation/deletion；训练一个小的 stop/value head 每 256–512 token 或语义步骤读一次当前 hidden state；大多数时候只跑一个小分类头 额外 transformer 计算接近 0；校准和数据生成是一次性成本
保守线上版 在推荐论文版基础上保留少量 probe 数据 只有停止头“不确定”时才做一次短 answer probe，并要求连续两次信号一致 简单题通常能节省很多 token；难题只增加少量 probe 成本

部署时最重要的工程原则是：sibling rollout 和步骤删除不能放在线上。它们用于离线学习“继续计算是否值得”的监督信号；线上只使用当前前缀已经产生的 hidden state、答案置信度、答案漂移/重复信号和一个训练好的 value head。

如果模型本来就在逐 token 生成，最后一层 hidden state 已经存在，接一个线性层或两层 MLP 来预测 stop / continue / uncertain 几乎没有额外成本。真正会增加成本的是重新生成一份答案 probe。这个 probe 可以利用已有 KV cache，不必重新计算整个 prefix；例如每 512 token 检查一次、每次只生成约 16–32 个答案 token，成本通常远低于让模型继续生成几千个冗余 token。

一个可执行的最小版本如下：

  1. 用基线模型离线生成完整轨迹，只在每 512 token 保存一个 checkpoint。
  2. 只对其中一小部分 checkpoint 做 continuation/deletion，得到“继续一段是否有收益”的标签；不要对每个 checkpoint 做完整 sibling rollout。
  3. 用冻结模型的 hidden state 训练一个小 stop/value head，不做昂贵的全模型 RL。
  4. 在独立 calibration split 上校准早停错误风险；阈值固定后再测试。
  5. 部署时默认只运行 stop/value head；只有预测不确定时才调用一次短 probe。

论文必须报告净成本，而不只是生成 token：

净节省 = 原始 CoT 的 transformer FLOPs - 停止器、probe、KV cache 和控制器的额外 FLOPs。

如果实验只报告 completion token，而不计 probe 和控制器，容易得到虚假的效率提升。建议至少报告三组结果：只用 hidden-state head、head 加 selective probe、以及朴素多 rollout 版本；这样可以清楚说明方法的科学上限和工程可用版本。

方向 1 的详细可实施方案（建议先做这个版本）

下面给出一个可以直接开始写代码的最小方案。它不修改基础模型，不先做全模型 RL，只训练一个小停止控制器；这样先验证研究问题是否成立，再决定是否加入 RL。

固定设置。

  • 基座模型：先用 DeepSeek-R1-Distill-Qwen-1.5B 跑通流程，再用 DeepSeek-R1-Distill-Qwen-7B 做主结果。两者都冻结，不更新语言模型权重。
  • 数据：第一阶段用 GSM8K；第二阶段用 MATH-500/AMC23；最终测试用 AIME24/25 和一个完全不参与训练、校准的数学集。
  • 解码：temperature 0.6、top-p 0.95、最大推理长度 8,192 tokens；在每个 512-token checkpoint 和自然语义步骤边界检查一次。
  • 切分：严格按题目切分，70% controller training、15% calibration、15% test；同一道题的不同 rollout 和不同 prefix 不能跨 split。
  • 最小预算：前 512 tokens 不允许停止；最大预算 8,192 tokens；答案 probe 最多触发一次，避免 controller 自己制造大量开销。

数据生成。

  1. 对 training/calibration/test 的问题分别生成一条完整 CoT，并保存每个 checkpoint 的 token offset、最后一层 hidden state、KV-cache 长度、当前答案候选和 verifier 结果。
  2. 对 training split 中每个 checkpoint，只抽取一小部分做离线 continuation label：从该 prefix 继续生成 B=256 tokens，采样 K=2 条 continuation，然后强制结束 thinking 并用 verifier 判断答案。不是每个 checkpoint 都做完整 sibling rollout。
  3. 对 calibration split 使用 K=4 做更稳定的阈值选择；test split 只运行控制器，不使用未来 continuation 标签。

监督信号。

对题目 q 在 checkpoint t 定义：

  • y_t：当前 prefix 强制回答是否正确；
  • y_{t+B}^{(k)}：第 k 条 continuation 后强制回答是否正确；
  • g_t = mean_k(y_{t+B}^{(k)}) - y_t：再花一个 block 的经验收益；
  • c_t = 1 - y_t：现在立即停止的错误指示。

控制器输入只包含部署时可见的 phi_t：最后层 hidden state 的低维投影、当前答案 log-prob/entropy、最近两个 checkpoint 的答案是否变化、重复/回溯特征、当前 token 数和 KV-cache 长度。g_t、y_{t+B} 和 gold answer 只用于离线训练标签，绝不进入线上特征。

控制器结构。

  • correct_head(phi_t) -> p_t：预测当前 prefix 直接结束时正确的概率；
  • gain_head(phi_t) -> g_hat_t：预测继续 256 tokens 的期望收益；
  • 一个两层 MLP（hidden size 256）即可，参数量远小于基座模型。

训练损失使用 BCE(p_t, y_t) + 0.5 * Huber(g_hat_t, g_t)；先不加 RL。为了避免按题目长度产生偏差，loss 按题目平均，而不是按 checkpoint 数量平均。

线上决策。

生成到 checkpoint t
如果 t < 512：CONTINUE
否则读取 p_t 和 g_hat_t
如果 p_t >= tau_safe 且 g_hat_t <= tau_gain：STOP
如果 p_t < tau_safe 且 g_hat_t > tau_gain：CONTINUE
否则：触发一次短 answer probe
    probe 仍然稳定且 p_t 较高：STOP
    其他情况：CONTINUE

tau_safe 和 tau_gain 不手工拍脑袋设置。在 calibration split 上枚举一组候选阈值，对每道题完整模拟一次停止策略；题目级损失为 1[最终答案错误]，成本为停止时的生成 token 数。选择在错误风险的 Clopper–Pearson 上置信界不超过 alpha（主结果 alpha=0.05，严格结果 alpha=0.01）时，平均 token 最少的一组阈值。这样处理了同一题多个 checkpoint 之间的相关性，比把每个 checkpoint 当成独立样本更稳妥。

部署成本的可核算版本。

  • 在线 stop/gain head：每个 checkpoint 一次小 MLP；hidden state 已由正常生成得到，额外 transformer forward 为 0。
  • checkpoint 检查频率：每 512 tokens 一次；8,192 最大长度最多 16 次。
  • selective probe：只在不确定状态触发，最多一次，生成 16–32 个答案 token并复用已有 KV cache。
  • 离线成本：若有 N 条训练轨迹、平均 L tokens，反事实标签成本约为 O(N * L/B * K * B) 生成 tokens；建议先在 2,000 条题/轨迹上做 pilot，再扩展。
  • 报告指标：基座总生成 FLOPs、controller FLOPs、probe tokens、KV-cache memory、wall-clock latency，最后给出净 token/FLOP savings。

最小基线和消融。

主基线：Vanilla full CoT、固定 1k/2k/4k/8k budget、confidence-only early exit、answer-agreement early exit、PUMA/ConCISE、OS-Pruner、Conformal Thinking。必须做以下消融：

  1. 只有 correct_head，没有 gain_head；
  2. 只有 gain_head，没有风险校准；
  3. 有校准但不做 counterfactual continuation；
  4. hidden-state-only 与 hidden-state + selective probe；
  5. 使用完整未来轨迹标签的 upper bound，与严格 prefix-only controller 对照。

通过标准。

第一阶段不追求 SOTA，先判断问题是否值得继续：在 MATH-500 上，相同 accuracy 下净 token 减少至少 20%，controller+probe 的额外 FLOPs 小于节省 FLOPs 的 10%，alpha=0.05 的测试错误率不超过校准上界太多，并且在 AIME/跨模型测试上没有严重 underthinking。如果只能节省 completion tokens、不能节省端到端 FLOPs，或者风险在分布外题目上失效，就停止这条路线。

实现顺序。

  1. 只做 full CoT checkpoint 记录和 forced-answer verifier，确认每个 prefix 的标签可靠；
  2. 训练 correct_head，先验证 confidence-only 是否有可预测性；
  3. 加入少量 continuation，训练 gain_head；
  4. 做题目级 calibration 和严格 test；
  5. 最后才加入 selective probe、跨模型和真实 latency；
  6. 只有当上述版本成立，才考虑把 stop head 蒸馏回基座模型或加入 RL。

方向 2：Opportunity-Cost Reasoning for Shared Mathematical Budgets

背景：现实中预算往往是“整场考试共享”的

大多数论文让每道题各自拥有一个独立上限：每题最多生成 8,000 token。这样做掩盖了一个实际问题：如果一次请求里有 20 道题，总共只有 100,000 token，某一道题多花 5,000 token，就意味着其他题少了 5,000 token。

这时，“每道题都压短一点”不是最优策略。更重要的是判断：继续当前题的下一段推理，带来的得分是否值得牺牲另一道题的预算？ 这就是 opportunity cost（机会成本）。

一个具体例子

现在有 3 道题、总预算 1,000 token：

  • 题 A 很简单，再给 100 token 基本不会增加得分；
  • 题 B 中等，再给 200 token 有较大概率从错变对；
  • 题 C 很难，再给 500 token 仍然只有很小成功率。

逐题独立的模型可能按输入顺序把 600 token 耗在 A 上，再把剩余预算给 B 和 C。共享预算控制器应该及时停止 A，把预算转给 B；对 C 观察一小段后，如果继续的成功概率仍然很低，就放弃或只保留一个低成本尝试。

这篇论文具体研究什么

把每道题当前的状态看成一个“候选项目”：它有当前答案、已经花费的 token、继续一个 block 后变好的概率、以及继续所需成本。每轮选择一个项目继续，直到总预算用完。

可以先用容易解释的 UCB/Thompson sampling：如果某题的“可能收益上界 / 额外成本”低于其他题，就停止给它分配预算。以后再用 RL 学习更复杂的切换策略。

它和方向 1、3 的区别

  • 方向 1 问“一道题现在停不停”；方向 2 问“下一笔计算给哪一道题”。
  • 方向 2 不要求删掉某道题已经写出的证明步骤，重点是题目之间的预算竞争。
  • 方向 3 是识别和删除 load-bearing 之外的步骤；方向 2 可以直接使用完整轨迹，但要决定是否继续投入。

怎么证明它有用

建立 shared-budget math benchmark：随机组成不同难度和分值的题组，给一个总 token/FLOP 上限。比较平均每题独立预算、按输入顺序处理、oracle difficulty allocation 和新控制器。

指标是总得分、每题得分、总 token、预算利用率、放弃后的救援率、切换次数和 allocation regret。必须证明它比“每题固定预算”提高整组总分，而不是只让某几道题变好。

主要风险

如果只展示更聪明的调度，而没有展示模型何时放弃、何时回收预算、何时重新进入困难题，审稿人可能认为这只是系统调度，不是 reasoning 论文。需要把题内状态变化和跨题决策同时报告。

方向 3：Proof-State / Verifier-Grounded Reasoning Compression

背景：文字步骤和数学状态不是一回事

一段 CoT 可能写了十句话，但真正改变数学状态的只有两三步。例如解方程 2x+3=11 时，真正关键的是“移项得到 2x=8”和“除以 2 得到 x=4”；“我们现在来仔细检查”“重新说明题目条件”是语言层面的内容，不一定改变证明状态。

现有的语义相似度剪枝或 LLM judge 可以猜某句话是否重复，但它们可能把“看起来相似、实际承担逻辑作用”的步骤误删。更可靠的办法是让 verifier 告诉我们：删除这一步后，形式证明状态、程序 AST 或可执行约束是否仍然成立。

这篇论文具体研究什么

不是问“这句话读起来像不像废话”，而是问：删除或合并这一步后，解题状态是否保持等价？

在 Lean/miniF2F 中，proof state 是当前还剩哪些目标、有哪些假设；在可执行数学程序中，程序状态是变量和约束；在普通 MATH/GSM8K 中，可以用符号计算器、答案 verifier 或最终方程作为较弱的替代。

一个具体例子

原始推理：

  1. 设原数为 x。
  2. 增加 20% 后是 1.2x。
  3. 再减少 20% 后是 0.8×1.2x。
  4. 题目说结果为 96，所以 0.96x=96。
  5. 因此 x=100。
  6. 再次把 100 代回去检查，仍然是 96。

如果 verifier 已经确认第 5 步满足约束，第 6 步可能是可删的；但如果第 4 步的系数写错，删除第 6 步会放过错误。压缩器应该保留会改变约束状态的步骤，而不是简单保留最短文字。

方法流程

  1. 把完整 CoT 切成步骤，并记录每一步前后的 proof state / AST / verifier state。
  2. 做删除、合并、重排等干预，检查最终证明或程序是否仍可执行。
  3. 用这些“删了仍成立 / 删了就失败”的标签训练压缩器或宏步骤生成器。
  4. 约束压缩后的轨迹在 verifier 上通过，并比较 token、可读性和泛化。

它和另外两条的区别

  • 方向 3 主要在 已有轨迹生成之后或训练时压缩内容；不是在线决定何时停止。
  • 它的核心证据是 verifier-preserving，不是置信度或长度相关性。
  • 它最适合 Lean、形式化数学和可执行程序；普通自然语言数学只能做弱验证，因此研究范围要说清楚。

怎么做实验和主要风险

第一阶段可在 Lean/miniF2F 或带程序 verifier 的数学任务上做严格实验，再迁移到 MATH/GSM8K。指标包括证明通过率、token 压缩率、删除错误率、自动验证时间和人工可读性。必须和 STOP、RECAP、ChainPrune、纯语义相似度剪枝比较。

主要风险是它可能只对形式化数学有效，最后变成 formal-methods 论文；自然语言数学的 verifier 太弱时，不能声称“严格证明步骤必要性”。因此更适合作为第二阶段，或作为方向 1 的反事实必要性模块。

5. 推荐论文结构

如果完成撞车审计后仍选择方向 1，论文结构应改成“明确缺口 + 对照审计”，而不是把已有组件重新包装：

  1. 先复现 CROP、Conformal Thinking、BLADE、LearnStop、AERA、SuCo/Settle 的共同评测协议。
  2. 用问题级严格切分，测量同一风险目标下的净 token/FLOPs/延迟，计入 probe 和 KV-cache 成本。
  3. 明确提出一个尚未被已有工作覆盖的缺口，例如在线分布变化下的 anytime 风险保证，或 STOP 相对 CONTINUE 的反事实因果上界。
  4. 只为这个缺口设计新模块，并给出理论假设、可证伪边界和专门消融。
  5. 如果新模块只带来普通的 learned stopping 增益，就把结果定位为复现/系统研究，不声称全新算法。

不要把论文贡献写成“我们组合了 conformal + causal + RL”。应写成一个可检验的问题：能否在不读取未来轨迹和 gold answer 的条件下，用 prefix-observable evidence 给出风险受控的最小充分停止决策？

6. 复现和算力建议

  • 第一版不必训练 32B；用 Qwen2.5-Math-7B、DeepSeek-R1-Distill-Qwen-7B、Qwen3-8B 中的两个即可。
  • 先生成一次完整轨迹缓存，再离线构造 prefix checkpoints；停止器训练/校准必须按 problem-level split，不能把同题不同 prefix 分到 train/test 两边。
  • 报告真实端到端 latency/FLOPs；只报告 completion token savings 会被 AERA、ReCo 等工作指出的 controller/probing/KV 成本反驳。
